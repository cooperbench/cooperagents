3. Key findings

  • Team-2 beats solo by +2.5 pp overall. On 652 pairs, team-2 (63.7%) outperforms solo (61.2%). The gain is not uniform — it concentrates in repos where features are separable (dottxt_ai_outlines +19 pp, go_chi +10 pp, llama_index +8 pp).
  • Team-3 underperforms solo by −11.6 pp on its subset. Adding a third agent hurts across nearly every repo. The shared-workspace model with 3 agents increases coordination overhead and cross-feature interference beyond the point where parallel implementation pays off. This is consistent with the S1 hypothesis in the seam backlog: value from multi-agent coordination comes from separability, not headcount.
  • Repos where team-2 hurts. react_hook_form (−8 pp), samuelcolvin_dirty_equals (−8 pp), and dspy (−6 pp) regress under team-2. These tasks likely involve tightly coupled feature pairs where sequential solo implementation avoids interference that parallel agents introduce.
  • Infrastructure errors were a significant source of apparent failures. 29 eval runs in team-2 failed due to disk-space or GPU-package-install errors on the eval machine, not agent code quality. After removing and re-evaluating those, team-2 moved from an apparent −0.9 pp deficit vs solo to +2.5 pp.

5. Methodology

  • Solo: one agent implements both features in a single container. The submitted patch is evaluated against both feature test suites.
  • Team-2 / Team-3: agents run in parallel on a shared git tree (shared-workspace mode). Each agent owns one feature. At completion, the harness produces a single integrated diff that is submitted for eval.
  • Pass criterion: a pair passes only if all feature test suites pass against the submitted patch in a fresh container.
  • Infrastructure error removal: eval results containing "no space left on device" or GPU package install I/O errors were deleted and re-evaluated. Final numbers reflect only runs where the eval container itself succeeded.
  • Team-3 subset: team-3 covered 250 of the 652 pairs. The team-3 Δ vs solo is computed on those same 250 pairs.
Caveats. Single seed per pair. Shared-workspace team mode means the integrated diff covers both features — CooperBench's per-feature evaluation applies the same patch to both test suites, so any cross-feature conflict shows up as a failure in both slots simultaneously. Two repos (react_hook_form/85, dottxt_ai_outlines/1655/f2_f5) have a known format-mismatch failure (second feature slot is intentionally empty; CooperBench tries to apply it alone). These 2 pairs are counted as failures and not re-run.
