# Qwen3.5-9B thinking ablation on cb-mixture-36

The completed comparison is **non-thinking versus worker-only thinking**, with
three independent runs per setting. **Long thinking has not been tested.** In
the worker-only setting, both workers use Qwen's chat-template
`enable_thinking=true`; the coordinator remains enabled with
`enable_thinking=false`. In the non-thinking setting, all three agents use
`enable_thinking=false`. These are the labels used below.

## Fixed setup and provenance

- Dataset: the same 36 training feature pairs in
  [`datasets/cb-mixture-36/manifest.json`](../../datasets/cb-mixture-36/manifest.json),
  pinned to CooperBench `63b9d44d9f39a02fccf5bf0052db48a917a011fd`.
  All 17 task images passed gold-feature qualification. The evaluator copy has
  only the byte-preserving large-patch transport fix; benchmark tests and
  reference patches are unchanged.
- Model: Qwen3.5-9B on the five-replica NLP SGLang router, using temperature
  `1.0`, top-p `0.95`, top-k `20`, and presence penalty `1.5`. Both settings
  use the same sampling values; the chat-template thinking switch is the
  requested difference. This is not an OpenRouter experiment.
- Harness: two mini-SWE workers per pair, shared Git and cooperation tools,
  event-triggered coordinator and completion gate enabled, 1,000 steps and
  3,600 seconds per worker. Repair and presub-merge are disabled. Each round
  runs up to ten pairs concurrently and evaluates them serially, on
  `visionlab-dgx1` with 20 CPUs, 128 GiB and an eight-hour Slurm limit.
- Source: non-thinking `676daba`; worker-only thinking `cd42039`. The latter
  adds only the worker-specific thinking override and its request-level test.
  Private model profiles are outside source snapshots and run records.
- Campaign records: non-thinking
  `/nlp/scr/chency/projects/cooperagents/runs/20260923-cb36x3-676daba`;
  worker-only thinking
  `/nlp/scr/chency/projects/cooperagents/runs/20260923-cb36x3-worker-thinking-cd42039`.
  Their round records contain exact run paths and job IDs. The second campaign
  also has `summary.json`.

All six rounds have 36 `result.json` and 36 official `eval.json` files; none
of those evaluation files reports an evaluator error. Across three rounds,
non-thinking passed **30/216 features and 9/108 pair attempts**; worker-only
thinking passed **26/216 features and 8/108 pair attempts**. Each setting had
**six distinct pairs** that passed both features at least once. Only two such
pairs overlap across settings: `pallets_jinja_task:1559:7,9` and
`pallets_jinja_task:1621:2,9`. In worker-only thinking, the latter passed in
all three rounds. The scores do not show an accuracy gain from enabling worker
thinking in this setup. Three runs and the low pass rates do not establish a
general model-quality conclusion.

## Execution caveats

- Non-thinking round 1 produced all 36 scores but Slurm reported
  `OUT_OF_MEMORY` (`0:125`), so it is not a clean infrastructure success.
  Its score is retained with this qualification; the other five jobs ended
  `COMPLETED` (`0:0`).
- Worker-only thinking round 2's `pallets_click_task:2800:1,3` official tests
  ran into the evaluator's execution timeout: both features have exit code
  `124` and failed. This is represented in the official scores, not as a
  missing evaluation. Model requests also hit the existing 240-second hard
  timeout and were retried during generation.
- Slurm batch `MaxRSS` in round order was `127727246K`, `14797205K`,
  `13636649K` for non-thinking and `41506355K`, `3532263K`, `57383216K`
  for worker-only thinking. Batch RSS does not measure all container memory.
  The worker-only round 3 cgroup briefly reached its 128 GiB cap, mostly in
  file cache, but recorded `oom_kill=0` and completed normally.
- The 36 pairs are the training selection, not a held-out test set. Keep all
  three rounds separate when reporting variability; do not select only the
  best round as the setting's score.
